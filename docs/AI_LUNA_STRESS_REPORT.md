# Luna 고정 심화 검증 및 보완

검증일: 2026-11-17. 모든 호출은 gpt-6-luna, 실제 OpenAI API + 합성 MOCK 상태로 실행했다. 실제 LG 가전 제어는 하지 않았다.

## 결과

| 단계 | 결과 | 해석 |
|---|---|---|
| 새 문장 20개 × 2회, 보완 전 | 최초 채점 38/40 | 범위 내 선택 위임 요청 2건의 기대값이 잘못되어 있었다. 원본 결과는 보존했다. |
| 같은 문장, 지시문·서버 보완 후 | 40/40 | 수정된 평가 기준 사용. 정확도 5% 향상으로 해석하면 안 된다. |
| 별도 새 문장 8개 × 2회 | 최초 채점 14/16 | '아래칸이 200도 넘으면'을 실제 온도와 설정 온도 중 무엇인지 모호하다고 보고 두 번 모두 미적용. 추측 적용하지 않는 것이 타당하다. 원래 기대값과 결과를 보존했다. |
| 위 조건을 '아래칸의 설정 온도'로 명시 × 2회 | 2/2 | 아래칸 195도, 위칸 유지 확인. |
| 실제 웹 화면 자연어 실행 | 성공 | 전원 켜기 유지 + 온도 정정 + 상대 계산을 결합한 요청으로 POWER_ON, 23.5도 확인. |

단순 성공률을 합산하지 않는다. 일부 평가 기대값을 결과 관찰 후 정정했으며, 데이터 규모가 작고 표현마다 두 번만 실행했다. 일반적인 정확도·모든 표현의 안정성을 보장하지 않는다.

## 평가 기준 정정

- “23도에서 25도 사이 아무거나 골라 켜줘”는 사용자가 선택 권한을 명시적으로 위임했다. 해당 범위와 기기 간격을 만족하는 값 및 전원 켜기를 정답으로 판단한다. “적당히 해줘”처럼 범위와 기준이 없는 요청과 구분한다. 최초 파일의 2건은 모델 실패가 아닌 채점 기준 오류다.
- “오븐이 200도 넘으면”은 실제 센서 온도를 의미할 수 있다. MOCK에는 설정 온도만 있으므로 설정값을 센서값처럼 대체하면 안 된다. 실패로 표시된 두 건은 보수적인 응답이며, 명확한 설정 온도 조건으로 후속 검증했다.

## 구현 보완

- AI 지시문에서 명시적인 범위 내 위임을 허용하고 실제 온도·목표 온도를 구분했다. 다중 구역의 대상이 빠지면 확인하도록 명시했다.
- AI 요청 시작 시 프로필·상태 해시를 보존하고, 적용 잠금 안에서 재조회해 비교한다. 처리 중 상태가 바뀌면 오래된 기준으로 계산한 값을 거절한다.
- 오프라인 제품은 유료 모델 호출 전에 차단한다.
- AI 변경 목록의 필드·항목 수·식별자 형식을 검사한 뒤 기존 지원 기능·범위 검증으로 전달한다.
- 오프라인 단위 테스트 45개 통과: 상태 변경 경쟁, 오프라인 선차단, 잘못된 AI 출력 차단 포함.

## 화면 및 재현

최신 실행 서버: http://127.0.0.1:8767 (MOCK). 기존 8765 서버와 메모리 상태는 별개다. 브라우저 자동 실행 명령이 차단되어 최신 코드의 별도 서버를 사용했다.

- 화면 캡처: `screenshots/ai-luna-execution.png`, `screenshots/ai-luna-page.png`
- 화면에서 요청: “에어컨 켜고 22도로 해줘. 아, 온도만 취소하고 지금 설정된 25도보다 1.5도 낮춰줘. 켜는 건 그대로 진행해.”
- 실제 생성 값과 MOCK 재조회 값 모두 전원 POWER_ON, 목표 온도 23.5 확인.
- 자동 상세화면 갱신으로 비워진 입력란에 같은 제출 문장을 다시 표시한 뒤 캡처했다. 생성 결과와 상태는 수정하지 않았다.
- 유료 검증 스크립트: `tests/evaluate_ai_stress.py`, `tests/capture_ai_demo.py`
- 원본: `AI_STRESS_baseline.json`, `AI_STRESS_revised.json`, `AI_STRESS_holdout.json`, `AI_STRESS_explicit_sensor_followup.json`

모델은 변경하지 않았다. API 기본 추론 설정, 출력 상한 1500토큰, 45초 제한을 유지했다. 추가 모델 검증 호출 없이 서버에서 확정적으로 검사할 수 있는 부분을 보완했다. 자연어의 의도 해석 자체는 여전히 모델에 의존한다.
