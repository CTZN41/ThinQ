## 비교 원칙

1. 제품 동일성: 정확한 모델명과 접미사, 설명서 적용 모델 목록 확인.
2. 세탁 목적: 의류·소재·오염·물기·구김 선호 등 사용 경험 추출.
3. 사용자 선택값과 관찰값 분리: 수온 설정 40℃와 관찰 소요 시간 40~50분을 다른 필드로 저장. 45분 명령으로 자동 변환하지 않는다.
4. 코스 의미 비교: 명칭 일치만으로 같은 코스라 판단하지 않고 대상 소재·부하량·허용 옵션을 비교.
5. 코스별 제약: 수온·탈수·헹굼 조합, 최대 세탁물량, 옵션 간 금지 조건 검사. 제품 정격 용량 비율로 세탁 시간을 늘리거나 줄이지 않는다.
6. 목표 유지: 뽀송함을 곧바로 강한 탈수나 건조로 해석하지 않는다. 건조까지 포함된 경험인지 필요한 경우 질문.
7. 근거 수준: 공식 확인 / 사용자 진술 / AI 제안 / 미확인을 각 필드에 저장. 미확인 조합은 실행 차단.
8. 실행 계층: 선택 가능한 설정과 원격 API로 설정 가능한 항목을 구분. 첫 단계는 가상 실행만 사용.

## 변환 결과 화면

구형 모델 선택 → 자연어 경험 입력 → 필요한 질문 → 신형 모델 비교 → 근거가 붙은 설정안 → 모의 실행.

결과표 열: 원문 정보 / 의미 / 신형 대응값 / 근거 / 유지·변경·미확인 / 변경 이유.

예: '40도에서 40~50분 돌리니 뽀송했다'
- 수온 40℃: 사용자 진술. 신형 제품 수준에서는 존재하나 선택 코스에서 허용되는지 추가 검증.
- 40~50분: 관찰 시간인지 설정 시간인지 미확인. 관찰값이면 시간 명령을 생성하지 않는다.
- 뽀송함: 결과 선호. 탈수/건조/자연건조 범위 확인 후 해석.
- 코스·소재·부하량 미상: 즉시 실행하지 않고 변환에 필요한 정보만 질문.

## 첫 테스트 범위

우선 WW90J3000KW → FX25GFG의 드럼→드럼 조합. 수온 유지, 코스 대응, 탈수·헹굼 옵션 보존을 검증한다. 원본 후보 3종은 준비하되 첫 조합의 검증된 프로필을 완성한 뒤 확장한다. 통돌이→드럼, 건조 결과 재현은 후속 범위로 둔다.

합격 기준: 모델 혼동 없음, 명시한 값 보존, 없는 기능 생성 없음, 미확인 조합 차단, 필요한 경우 질문, 모의 상태가 검증된 설정과 일치. 세탁 결과·식감 같은 물리적 성능 재현을 주장하지 않는다.

## 구현 순서

1. 모델별 공식 설명서 확보 및 코스/옵션/제약 근거표 작성.
2. 해당 근거만 포함한 제품 JSON 프로필 작성. 테스트 전용 가정은 별도 synthetic 모델로 분리.
3. 구형 모델 선택 칸과 자연어 경험 입력 UI 구현.
4. 추출 → 비교 → 검증 → 모의 실행을 분리하고 실패·추가 질문 경로 구현.
5. 동일 경험을 구형 모델만 바꿔 넣어, 근거 없는 차등 변환을 만들지 않는지 검사.

Luna 모델을 유지한다. 이 기획 때문에 기존 실제 에어컨 설정이나 API 키를 변경하지 않는다.
