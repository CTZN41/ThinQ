# 복잡한 자연어 제어 평가

검증일: 2026-11-17. 실제 OpenAI API를 호출하되 가전은 매 요청마다 초기화한 메모리 MOCK만 사용했다. 실제 LG 가전 명령은 전송하지 않았다.

## 비교 결과

| 모델 | 기존 지시문, 14개 | 개선 지시문, 같은 14개 | 추가 6개 |
|---|---:|---:|---:|
| gpt-4.1-mini | 10/14 | 12/14 | 미실시 |
| gpt-4.1 | 10/14 | 14/14 | 6/6 |
| gpt-5.4-mini | 미실시 | 13/14 | 미실시 |
| gpt-6.1-sol | 미실시 | 14/14 | 6/6 |
| gpt-6-luna | 미실시 | 14/14 | 6/6 |
| gpt-6.1-terra | 미실시 | 14/14 | 6/6 |

최종 `.env.openai`의 모델은 **gpt-6-luna**로 변경했다. 처음에는 Sol로 변경했지만 사용자의 추가 요청에 따라 Luna·Terra도 평가했다. GPT-4.1, Luna, Terra, Sol 모두 같은 20개 사례를 통과했으므로 모델 간 우열을 확정할 수 없다. 이번 20개 호출의 평균 응답 시간은 Luna 약 2.0초, Terra 약 2.2초, Sol 약 2.5초였다. 3개 동시 요청 환경에서 관측한 값이며 반복 성능 시험은 아니다. 비용 비교는 수행하지 않았다. 테스트 범위에서 동작이 충분했고 응답이 더 빨랐던 Luna를 기본값으로 선택했다.

## 시험 기준

- 실제 변경된 MOCK 상태가 예상 변경과 정확하게 일치해야 한다.
- 정상 요청은 적용되고, 모호·미지원·범위 초과 요청은 전체 미적용과 설명을 반환해야 한다.
- 모델 문장의 그럴듯함만으로 성공 처리하지 않았다. 서버 검증에 걸린 잘못된 출력도 모델 성공으로 처리하지 않았다.
- 상대 온도 계산, 부정, 문장 내 정정, 조건 분기, 특정 오븐 구역, 실행 금지, 예약 미지원, 여러 제품 미지원, 범위·간격 위반을 확인했다.

## 발견한 문제와 수정

기존 mini는 모호한 요청에 임의로 24도를 정하거나, 범위 밖 온도 요청과 함께 들어온 전원 명령만 실행했다. GPT-4.1도 기존 지시문에서는 일부만 적용했다. 모델 승격만으로 해결되지 않았다.

AI 지시문을 단계별로 보완했다. 모든 행동·대상·시점·조건을 먼저 파악하고, 하나라도 처리 불가능하면 전체 변경을 비우도록 했다. 요청하지 않은 전원·온도 추정 금지, 모의 온도 설정과 전원은 독립적이라는 점, 상태 기반 연산 및 실행 금지를 명시했다.

개선 후 mini와 GPT-5.4 mini는 문장 중 온도 정정을 전원 명령 취소로 잘못 해석하는 사례가 남았다. GPT-6.1 Sol과 GPT-4.1은 이번 평가에서 요청한 전원 명령을 유지했다.

## 재현 및 한계

유료 실행: `.venv\Scripts\python.exe -X utf8 tests/evaluate_ai_manual.py`

`OPENAI_MODEL` 환경변수로 비교 모델, `EVAL_SUFFIX`로 결과 파일 접미사, `EVAL_SET=holdout`으로 추가 6개를 선택한다. 원자료는 `AI_EVAL_*.json`에 있다. 키와 인증정보는 포함하지 않는다.

각 사례는 모델·지시문 조합마다 1회 평가다. 지시문을 다듬는 데 사용한 14개는 독립 평가가 아니며, 추가 6개도 같은 계열의 제한된 수작업 사례다. 전체 한국어 정확도나 반복 실행 안정성을 보장하지 않는다. API 기본 추론 설정과 최대 출력 1500토큰, 45초 제한을 사용했다.

지원하지 않는 기능을 거절하는 것은 현재 MOCK 범위에서 올바른 동작이다. 모델 승격으로 실제 프로필에 없는 제습·예약·다중 제품 제어가 생기지는 않는다. 한 요청 내 문맥만 처리하며 이전 대화 기억은 없다.
