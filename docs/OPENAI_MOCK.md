# 자연어 AI 모의 제어 테스트

## 실제 OpenAI 연결 검증 (2026-11-17)

사용자가 `.env`의 `OPENAI_API` 항목에 저장한 키를 AI 로더가 읽는 `.env.openai`의 `OPENAI_API_KEY`로 연결했다. 모델은 `gpt-4.1-mini`로 설정했다. 이후 키 변경은 `.env.openai`에서 수행한다.

실제 OpenAI 호출과 메모리 MOCK 적용을 검증했다:

- “거실 에어컨을 켜고 24도로 맞춰줘”: 전원 POWER_ON 및 온도 24 설정 생성·적용 성공.
- “거실 에어컨을 99도로 맞춰줘”: 허용 범위 18~30도 안내와 빈 변경 목록 반환, 미적용.

이 두 사례는 동작 확인이며 모든 자연어 표현의 정확도를 보장하지 않는다. 실제 LG 가전 명령은 전송하지 않았다.

## 시작

1. 프로젝트 루트의 `.env.openai`를 열고 `OPENAI_API_KEY=` 뒤에 본인 OpenAI API 키를 입력해 저장한다. 채팅에 보내지 않는다.
2. `OPENAI_MODEL=gpt-4.1-mini`가 기본값이다. 계정에서 사용할 수 있는 Structured Outputs 지원 모델로 변경할 수 있다.
3. http://127.0.0.1:8765 에서 제품을 선택한다. 저장한 키는 요청마다 읽으므로 서버 재시작 없이 제품을 다시 선택하면 된다.
4. 거실 에어컨 선택 → “거실 에어컨을 켜고 24도로 맞춰줘” → **AI로 모의 적용**.

OpenAI에는 실제 API 키가 필요하며 API 이용료가 발생한다. 가전은 합성 데이터로만 테스트한다. ThinQ PAT나 실제 제품 정보는 이 기능에 사용하지 않는다. `.env.openai`는 Git 제외 대상이며 웹에서 제공하지 않는다.

## 흐름 및 범위

자연어 → OpenAI Responses API의 JSON Schema 출력 → 전체 설정값 검증 → MOCK 일괄 적용 → 결과 및 현재 상태 표시.

선택한 한 제품만 대상으로 한다. 지원 기능·값 범위·현재 모의 상태를 OpenAI에 전달한다. 대화 내역을 이어받는 채팅은 아니며 요청마다 독립적으로 처리한다. 모호한 요청은 빈 변경 목록과 질문을 반환하도록 지시한다. AI 판단의 정확도는 키 입력 후 실제 모델로 검증해야 한다.

서버에서 LIVE 실행을 차단한다. AI가 만든 명령도 기존 프로필 검증을 통과해야 하며, 범위를 벗어난 값은 부분 적용 없이 거절한다. 오류 시 자동 재시도하지 않는다. API 요청의 `store`는 false이다.

## 검증

키 없는 오프라인 테스트로 정상 변환 결과 적용, 잘못된 온도에서 전체 미적용, 추가 질문, LIVE 차단을 검증했다. 실제 OpenAI 호출은 사용자 키 입력 후 진행한다.
