# 기억하는 행동에서 새 제품 적응으로

## 변경 이유

사용자는 수온·탈수·시간을 정리해서 기억하지 않을 수 있다. 과거 설정을 정확히 입력해야 하는 흐름에서, 기억하는 행동·사용 목적·결과를 구분하고 필요한 질문 하나만 표시하는 흐름으로 변경했다.

## 구현

- 추출에 request_kind(경험 이전/사용법 질문/현재 결과 불만/불명확), remembered_behavior(기억하는 조작)를 추가했다.
- 버튼 누른 횟수, 표준 코스 이름, 구형 모델명만으로 수온·탈수 단계·의류 용도를 채우지 않도록 했다.
- 세션은 original_facts를 보존하고 추가 선택은 new_choices로 구분한다.
- 질문 순서는 의류 종류 → 미해결 상대 탈수/RPM → 이번에 쓸 수온이다. 한 번에 하나만 보여준다.
- 모르는 탈수는 비워둔다. 사용자가 모른다고 확인하면 과거 상대 진술을 보존하면서 그 조건을 제외해 후보 비교를 계속한다.
- 의류 종류를 모르면 적합한 코스를 추측하지 않고 확인할 때까지 선택을 기다린다.
- 이번에 선택한 수온을 과거 수온으로 표시하지 않는다. 새 선택/모름이 있으면 ‘새 시작 설정 선택 · 이전 설정 복원 아님’이라고 표시한다.
- 고급 입력은 기본적으로 접어두고, 필수 확인 전에는 후보 카드를 숨긴다.
- 저장·재불러오기에도 원래 추출값, 모름, 새 선택 구분을 보존한다. 기존 카드도 계속 읽을 수 있다.

## 검증

- 자동 테스트 78개 통과(새 회귀 테스트 5개 포함).
- 현재 설정 모델을 바꾸지 않고 실제 OpenAI 추출 4문장 검사: 4개 통과. 결과는 WASHER_NATURAL_PROBE.json. 작은 표본이므로 일반 정확도 지표로 해석하지 않는다.
- 브라우저에서 의류 선택 → 탈수 모름 → 이번 수온 선택 → 후보 선택 → 가상 실행 확인. 모바일 가로 넘침 및 JavaScript 오류 없음.
- 캡처: screenshots/washer-adaptation.png, washer-adaptation-mobile.png.

## 구현 경계

구형 제품 설명서의 버튼 순환·기본값과 신형 코스별 옵션 조합은 아직 연결되지 않았다. 비교는 기존 합성 프로필을 계속 사용하며 공홈 스펙을 실제 제어 가능 범위로 취급하지 않는다. 새 안내는 이 한계를 화면에 표시한다. 경험 이전 화면은 MOCK 전용이고 실제 제품 명령을 보내지 않는다.

다음 데이터 작업은 소수의 구형·신형 모델 설명서에서 코스별 기본값·선택 범위·동시 선택 제한과 근거 페이지를 검증해 프로필로 만드는 것이다.

## 후속 변경: 헹굼·탈수 항상 포함

사용자 결정에 따라 모든 후보는 세탁·헹굼·탈수를 포함한다. 과거 헹굼 횟수나 탈수 강도를 모르면 원래 facts는 비워두되, 실행 설정은 가상 코스 기본값을 사용하고 defaulted_fields에 출처를 표시한다. 가상 기본값은 헹굼 2회, 울/섬세 코스 탈수 약, 나머지 탈수 중이며 실제 LG 모델의 기본값이 아니다. 사용자가 명시한 값은 그대로 검증하고 우선한다. 화면에도 단계 포함과 코스 기본값 사용을 표시한다. 위의 ‘모르는 탈수는 비워둔다’는 과거 진술에만 해당하며 실행 설정에는 더 이상 해당하지 않는다.
