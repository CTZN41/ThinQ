# PHASE 5 — 검증 및 인수인계

2026-11-17 / 상태: 오프라인 검증 완료, 실기 검증 대기.

## 결과

- 전체 자동 테스트 35개 통과: 기존 18개와 신규 17개.
- 브라우저 smoke 테스트 통과: 미리보기/확인, 오프라인, 미지원, 모바일, JS 오류 점검.
- KR 기본 설정, PAT 없이 MOCK 모드 실행 확인.
- .env 미생성, 실제 PAT 미입력, 실제 계정 요청 및 실제 제품 제어 없음.
- 제품 클래스 30개 매핑 테스트 통과. 실제 지원 모델 수를 의미하지 않음.

## 요청 처리

localhost 전용 바인딩, Host/Origin 검사, 변경 요청의 CSRF 값 확인, 최대 요청 크기 제한, 화면에서 외부 문자열을 textContent로 삽입한다. 임의 서버 메서드 호출과 raw 제어 payload 입력은 제공하지 않는다. SDK 예외의 원문/인증 헤더는 화면으로 반환하지 않고 고정된 안내로 변환한다.

인증 만료·호출 제한·미지원·연결/제어 조건 오류의 대표 코드를 분류했다. 실제 API 오류 발생 테스트는 아직 하지 않았으며, timeout 대역 테스트로 자동 재전송하지 않는 것을 검증했다.

## 실행/종료

VS Code 기본 작업은 웹 MOCK 실행이다. `http://127.0.0.1:8765`로 접속한다. 터미널에서 실행한 경우 Ctrl+C로 종료한다. 이번 작업에서는 백그라운드 MOCK 서버를 실행했고, 작업 당시 PID는 10940이었다. PID는 이후 다른 프로세스에 재사용될 수 있으므로 숫자만 보고 종료하지 않는다. 포트가 사용 중이면 해당 프로젝트의 실행 중인 서버인지 확인하거나 다른 포트를 지정한다.

현재 의존성 고정 파일: `requirements-lock.txt`. 브라우저 재검증 도구는 별도 `requirements-dev.txt`에 둔다.

## 다음 실기 점검 순서

1. 사용자가 로컬 .env에 PAT를 설정하고 LIVE 모드로 시작한다.
2. 목록 조회와 각 제품 상세 조회를 먼저 수행한다.
3. 지원 기능, 프로필의 쓰기 값과 지역·모델 제한을 기록한다.
4. 선택한 제품 한 대의 명령을 미리보기 후 전송한다.
5. API 접수와 실제 물리 반영을 구분해 기록한다.

현재 코드는 로컬 단일 사용자 데모다. 외부 공개 서비스용 인증, 다중 사용자 토큰 보관, 분산 상태/명령 관리, 배포는 포함하지 않는다.
