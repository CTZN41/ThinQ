# AI 실제 연결

2026-11-17 사용자 요청으로 실제 PAT 연결과 AI 제어 화면을 준비했다. 사용자가 작동 테스트는 직접 진행한다고 지정했으므로 실제 제어 POST는 보내지 않았다.

- 주소: http://127.0.0.1:8768
- 실행: `.venv\Scripts\python.exe -m thinq_demo.web --mode live --ai-live --port 8768`
- 모델: 기존 gpt-6-luna 유지.
- 실제 제품 2대 조회 및 AI 버튼 활성화 확인. 검증 중 POST 0건.
- AI 출력의 단일 값을 제품별 실제 SDK 인자 이름으로 변환한다. 다중 인자 명령은 현재 AI 대상에서 제외한다. 전체 값 검증과 상태 변경 검사 후 순차 전송하며 일부 실패를 자동 재시도하지 않는다.
- 화면에서 API 요청 접수와 물리 작동 성공을 구분한다. 사용자가 결과 상태와 실제 제품 동작을 확인해야 한다.
- `--ai-live` 없는 LIVE 서버는 AI 실제 적용을 차단한다.
- 로컬 브라우저 자동 실행은 정책 차단, 내장 브라우저 연결도 native pipe 부재로 실패했다. 링크로 직접 접속 가능하다.

45개 기존 테스트 통과. 실제 기기 AI 제어 성공은 아직 검증하지 않았다.

## 제습 실행 실패 조사

**후속 사용자 확인 (2026-11-17):** 전원 켜기 → 제습 모드 순서 수정 후 사용자가 직접 실행하여 “잘 된다”고 보고했다. 이 시나리오의 실제 작동은 사용자 확인으로 기록한다. 다른 제품·전체 명령의 실기 검증 완료를 의미하지 않는다.

사용자 화면에서 AIR_DRY 다음 POWER_ON 순서의 계획과 일부 실패가 확인됐다. 읽기 전용 조회 시 두 제품 모두 POWER_OFF였고 AIR_DRY는 지원 목록에 있었다. 기존 구현은 첫 예외에서 멈추며 오류 코드를 버렸으므로 과거 실패의 정확한 원인은 복원할 수 없다. 전원 꺼짐 상태에서 모드 변경 거절 가능성은 가설이다.

명시적으로 요청된 에어컨 POWER_ON만 먼저 보내도록 순서를 정리했다. 새 전원 명령을 추가하지 않는다. 실패 시 숫자 오류 코드와 정제된 설명을 보존하고 UI에 전송 항목별 결과를 표시한다. 마지막 전송 결과는 서버 메모리와 읽기 전용 `/api/devices/{id}/last-result`에 유지한다. 원문 예외나 토큰은 보존하지 않는다. 테스트 47개 통과. 사용자 지정에 따라 실제 작동 재시험은 하지 않았다. 이 변경만으로 물리 작동 문제 해결이 확정된 것은 아니다.
