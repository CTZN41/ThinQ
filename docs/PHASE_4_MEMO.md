# PHASE 4 — 명령 준비·전송 코드

2026-11-17 / 상태: 실기 전송 코드와 대역 테스트 구현. 실제 가전 작동 검증은 수행하지 않음.

## 준비 단계에서 네트워크 제어를 하지 않는 방법

SDK 제품 객체에 실제 API 대신 CaptureAPI를 주입한다. 허용된 setter를 호출하면 SDK가 만든 payload를 메모리에만 받는다. CaptureAPI에는 네트워크 호출 기능이 없다. 그래서 모드·온도 변경 메서드가 START를 포함하더라도 준비 단계에서는 실제 시작되지 않는다.

단일 명령으로 구성된 payload만 받는다. 사용자 입력은 서버에서도 자료형·선택값·범위·간격·제외값을 검증한다. 준비 결과를 UI에서 보여 주어 단순 온도 변경에 START가 포함되는 등 부수 동작도 확인할 수 있다.

## 확인 단계

서버가 120초짜리 단회 미리보기 ticket을 발급한다. ticket은 최대 100개로 제한하고 만료 항목을 정리한다. 확인 시 ticket을 소비하고 최신 프로필·상태를 재조회한다. 준비 당시의 snapshot과 다르면 다시 준비하도록 한다. SDK로 payload도 다시 구성해 변경 여부를 확인한다.

그 후에만 실제 gateway의 `async_post_device_control`을 한 번 호출한다. 자동 재전송은 없다. 모의 모드에서는 MockCatalog만 변경한다.

## 결과의 의미

- MOCK: 메모리 값 변경만 수행. 물리 시뮬레이션 아님.
- ACCEPTED: SDK 요청이 정상 반환했고 상태도 재조회함. 실제 목표 달성을 자동 판정하지 않음.
- ACCEPTED_STATE_UNKNOWN: 요청은 정상 반환됐으나 재조회 실패.
- UNKNOWN: 전송 도중 오류. 이미 접수되었을 가능성을 배제할 수 없어 자동 재전송하지 않음.

원격 제어 활성화, 문 닫힘, 현재 운전 모드 등 제품별 조건은 LG 서버/가전에서 최종 거부될 수 있다. 모든 사전 조건을 프로그램에서 독자적으로 판정하지 않는다.

## 오프라인 검증

공식 SDK와 합성 프로필로 에어컨 전원 payload, 오븐 모드+온도+START+구역 payload를 만들고 확인했다. 읽기 전용 온도에서는 조합 명령이 생성되지 않도록 검증했다. FakeGateway로 명령 준비 시 호출 0회, 확인 시 1회, timeout 시 재시도 없음 및 결과 UNKNOWN을 확인했다.

이는 실제 LG 제품 연결 성공이 아니다. 실기 테스트 후 모델별 지원표를 보완해야 한다.

## 알려진 제한

미리보기와 확인 사이에 남은 시간·센서값 등이 바뀌어도 snapshot이 달라져 거부될 수 있다. 보수적인 데모 동작이다. 실기 응답을 확보하면 명령과 관련된 상태만 비교하도록 개선할 수 있다. 아직 MQTT 이벤트·목표 상태 도달 판정·제품별 모든 조합 명령을 구현하지 않았다.
